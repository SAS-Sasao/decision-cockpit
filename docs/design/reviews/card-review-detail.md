## R2〜R5 — 較正欠陥の連鎖(設計者が持ち込み、実測で潰した)

review-loop に続き、**改訂のたびに「正しい実装を落とすピン」を持ち込んだ**。すべて実測で発見・修正:

| R | 欠陥 | 実測 | 是正 |
|---|---|---|---|
| R2 | `grep -rl "REVIEW_DISPATCH_PAT" = 1` | 現物 **2**(spar-panel のエラー文言に一致) | `process.env.` 付きに(実測 1) |
| R3 | 関数レンジ `/^}/` 終端 | `}): Promise<…> {` で即閉じ(6行・0件) | `/^}$/` + シグネチャ1行の制約 |
| R3 | review-loop 置換の検出ピン | アンカー語が**置換前から 0** = 何も検出しない | 実測で1回だけ出現する語に変更 |
| R4 | **organize-role.sql の三竦み** | 改訂要求ピン × diff 0 凍結 × allowlist 未収載 = **どう実装しても CR-1 が落ちる** | 凍結を**行の計数**に分解 + allowlist へ |
| R5 | `git diff \| grep -c '^-'` = 0 | `--- a/…` ヘッダに必ず一致(未変更時は diff が空で**空成立**していた) | `--numstat` の削除列(実測: 追記 0 / 削除 1) |

**申告と現物の不一致**も1度発生: R2 で「S-12 / S-14 / S-15 を反映した」と報告したが本文に入っておらず、sec が現物確認で検出した(要約が先行した設計者の誤り)。

## 最終判定 — **全レンズ PASS**

- **sec**: 「秘密衛生・認可・同意ガード・露出面のいずれも**散文の約束ではなく機械判定と受容記録の両方**に落ちている」
- **data**: 「形状 CHECK は全域 / 索引・SQL・散文が一致 / 冪等キーの一貫性 / 機微データの受容が明文化 + 参照先への追記までピンで担保」。`--numstat` は「本命の不変量に対して**以前より強い**」(GRANT のその場書き換えも検出)
- **arch**: 「R1〜R4 で挙げた『正しい実装を落とすピン』『空成立するピン』『三竦み』はすべて解消、較正はいずれも**現物実測に裏付けあり**」
