## 4. 共通仕様

### 4.1 レイアウト
- デスクトップ web(基準 1440×900、左サイドバー 230px 固定 + メイン可変)。
- **サイドバー**: ロゴ / ビューナビ(6項目・アクティブ強調・未処理inboxバッジ) / ユーザー行(名前・ロール・ログアウト)。
- **トップバー(56px)**: 画面タイトル + サブ情報 / 同期ステータス(最終同期時刻・稼働インジケータ) / 壁打ち起動ボタン。

### 4.2 デザイントークン

| トークン | 値 |
| --- | --- |
| 背景 | `oklch(0.15 0.012 255)` / パネル `oklch(0.185 0.013 255)` |
| 罫線 | `oklch(0.26 0.014 255)` |
| 文字 | 主 `oklch(0.93 0.006 255)` / 補 `oklch(0.66 0.012 255)` |
| アクセント(ブランド) | ティール `oklch(0.78 0.11 195)` |
| アクセント(壁打ち・個人) | バイオレット `oklch(0.72 0.11 290)` |
| セマンティック | 良 `oklch(0.75 0.14 150)` / 注意 `oklch(0.80 0.13 75)` / 不良 `oklch(0.68 0.16 25)` |
| 書体 | UI: IBM Plex Sans JP / 数値・タグ・コード: IBM Plex Mono |
| スコア閾値 | ≥0.80 緑 / ≥0.65 琥珀 / <0.65 赤 |

### 4.3 認可・データスコープ(全画面共通)
- 生キャプチャ・壁打ち: 所有者(user_id)本人のみ参照可(アプリ層で強制)。
- 共有データ(timeline_records・索引・整理済み知識): 認証済みユーザーが参照可。user_id を持たない。
- ユーザー/ロール管理: admin のみ。

## 5. 画面詳細

### SC-01 ログイン(screenshots/sc01-login.png)
- 目的: Neon Auth によるサインイン。左: ブランド + フォーム / 右: システムステータス(GitHub同期×2 repo・Neon接続・整理ループ次回実行)。
- 入力: USER ID / PASSWORD。ログイン成功 → SC-02、失敗 → インラインエラー。

### SC-02 概観(screenshots/sc02-overview.png)
- 目的: 定量(組織スコア)と定性(判断ログ)を1画面で一望し、異常と着手先を即断。
- データ: timeline_records / metric_aggregates / capture_inbox(本人分)。
- ブロック: **KPIカード×4**(報酬スコア週・品質ゲート合格率・オープンタスク・未処理inbox。前週差分 + 6週スパークライン)/ **横断タイムライン**(報酬スコア面 + 合格率線・W22〜W27・判断ログ併記)/ **品質ゲート円形ゲージ + 内訳バー** / **最近の判断ログ**(改善幅表示)/ **今日の着手候補**。
- 操作: 判断ログ行 → SC-04(選択状態)/ 着手候補・「今日ビュー」→ SC-03。

### SC-03 今日(screenshots/sc03-today.png)
- 目的: オープン WBS/kanban から「どれに着手するか」を支援。データ: timeline_records(type=task)/ WBS / board.md。
- ブロック: サマリ帯×4(オープン・着手中・手戻りあり・平均スコア)/ **kanban 4列**(バックログ・着手中・レビュー・完了)/ タスクカード(タグ・org・手戻り↺n・スコア閾値色)。
- 操作: カード → タスク詳細(関連 decision・差し戻し履歴)。

### SC-04 ナレッジ再利用(screenshots/sc04-knowledge.png)
- 目的: 過去判断を pgvector 類似検索し、判断後の組織実績を時間軸で紐づけ提示。
- データ: timeline_records(type=decision, embedding)/ metric_aggregates / tag_synonyms。
- ブロック: 検索バー(類似検索 + タグチップ)/ 左: 結果リスト(日付・org・類似度 0〜1・要約・タグ)/ 右: 判断詳細(本文・判断後6週の報酬スコア推移・実績統計×3)。

### SC-05 振り返り(screenshots/sc05-retro.png)
- 目的: 週次/月次の品質トレンド可視化 + 同期間の判断ログ突き合わせ。
- ブロック: 週次/月次トグル / **LLM-as-Judge 3軸折れ線(0〜5・直近6期間)** / **報酬スコア4シグナル水平バー(完了度・品質ゲート・効率・Git規律)** / 品質ゲート合格率(棒)× 報酬スコア(線)複合チャート / 同期間の判断ログ並置。

### SC-06 キャプチャ + 壁打ち(screenshots/sc06-capture.png)
- 目的: メモ・課題・次の一手を capture_inbox(user_id 所有)へ保存し、壁打ちで判断を深める。
- 入力: kind チップ(status / issue / next_move。壁打ち結論は spar_conclusion 自動)/ トピック(任意)/ 本文(必須)。
- 表示: INBOX リスト(kind バッジ・未処理は琥珀枠)・未処理件数。
- 挙動: 保存 → 未処理で追加 → 整理ループ(朝07/昼12/夜19/深夜24)が処理し ai-war-room へ PR。壁打ちは文脈参照チップ(参照判断・類似度・スコア差分)付き応答。
- 制約: 機微データ(profile.md / minefield.md)は壁打ち文脈に含めない。

### SC-07 ユーザー管理(screenshots/sc07-admin.png)
- 目的: ユーザー一覧とロール割当(admin/member)。データ: Neon Auth / roles / user_roles。
- ブロック: ユーザー一覧(アバター・ロールバッジ・キャプチャ数・最終アクティブ)/ ロール&権限(人数・将来 permissions 拡張)/ アクセス制御の説明。

### 共通: 壁打ちスライドオーバー
- 全画面トップバー「壁打ち」→ 右 420px パネル + 背景ディム。構成は SC-06 の壁打ちと同一。✕ / 背景クリックで閉じる。

## 7. リポジトリ現状とのギャップ / 実装への割付(追補・2026-07-12)

MoC と、PASS 済み設計(auth-foundation / ingestion-foundation)・実データ調査(docs/research/m1-ssot-schema.md)との突き合わせ。**機能実装は既存マイルストーンを正とし、MoC は UI の到達目標**として扱う。

### 7.1 画面 × マイルストーン割付

### 7.2 データ整合の要注意点(実装時に MoC を読み替える箇所)

1. **報酬スコア4シグナルのラベル不一致**: MoC は「完了度・品質ゲート・効率(速度)・Git規律」だが、**実データの signals は `completed / artifacts_exist / excessive_edits / retry_detected`**(調査で確定)。表示は実データ準拠 — M1 詳細設計 §0-1 の確定ラベル(完了率 / 成果物あり率 / 過剰編集率 / リトライ率・発生系は低いほど良い)を正とする。
2. **LLM-as-Judge のスケール**: MoC は 0〜5 の折れ線だが、**格納は 0-1 正規化**(M1 設計確定)。表示スケールは 0-1(または %)を正とする。
3. **ルート名**: MoC は `/knowledge` `/retro` `/today`、現骨格は `/search` `/review` `/`(今日)。**M1-C は PASS 済み設計どおり app/review に実装**し、ルート再編(/retro 等への改名 + SC-02 を `/` に配置)は UI シェル対応のスコープで一括判断(PASS 済み設計の受け入れ条件を壊さない)。
4. スコア閾値(≥0.80 / ≥0.65)・デザイントークン(§4.2)は UI シェル対応時の共通定数として実装。

### 7.3 提案: 「UI シェル」を独立トピックとして設計する

サイドバー + トップバー + ダークテーマ + SC-02 概観 + ルート再編は、機能マイルストーンを横断する **UI 基盤**なので、
M1 実装完了後に **`/basic-design ui-shell`** として独立に設計 → review → /goal するのを推奨
(M1-C を最小のまま先に完了させ、見た目の引き上げを一括で行う — 機能と意匠の手戻りを分離)。
